# 游戏人格测评系统（GamePersona）

**项目方案 v0.4｜2026-10-14**

当前状态：第一阶段本地数据审计与第二阶段自动特征已通过；第三阶段共享评分、条件参考及独立工程验收已按 `model-stage3-v1` 通过，见 docs/STAGE3_STATUS.md。第四阶段本地网站、雷达图、PNG 与自动/浏览器样例验证已实现；用户已在外部浏览器验证真实登录及报告/图片一致，正式库实时读取和十二维报告已核实，外部实账号退出动作尚未观察，见 docs/STAGE4_STATUS.md，第四阶段尚未标整体通过。文中未被阶段状态明确冻结的候选公式与阈值仍不代表实测结论。数据使用条件和公网部署仍未验收。

本文使用三种决策状态：**已确定决策**用于约束首版范围和行为；**首版实验方案**作为可复现、可替换的建模起点；**待验证假设**必须通过数据与实验确认，不作为已证实的产品承诺。

## 一、产品目标与首版范围

### 1.1 产品目标

面向个人 Steam 玩家，根据可读取的真实游戏记录，结合游戏特征数据库，生成可解释、可视化、可分享的游戏偏好画像。

核心链路：

**Steam 身份验证 → 可见游戏记录 → 游戏特征映射 → 行为证据累计 → 评论样本参考分位 → 十二维报告与可选类型 → 分享卡**

“游戏人格”是产品表达，实际估计的是游戏偏好与行为风格，不直接等同于现实人格、能力或经过认证的心理测量结果。游玩记录是偏好推断的证据，不是玩家喜欢程度的直接测量。

### 1.2 核心原则

1. 连续评分优先：十二维画像是主要结果，四字母类型是可缺省的摘要。
2. 分别计分：每个维度拥有自己的证据，不要求十二维之和固定，也不强制一组两端互斥。
3. 口径透明：展示分数的参考群体、数据覆盖情况与适用限制。
4. 解释可追溯：从报告回溯到贡献游戏、标签依据、输入快照及模型版本。
5. 验证驱动：维度、时长函数与类型阈值允许依据实验结果修改，不为保留 16 型而牺牲有效性。

### 1.3 首版交付与后续范围（已确定决策）

| 能力 | 首版交付 | 后续扩展 |
|---|---|---|
| 用户入口 | Steam 登录及可见游戏记录读取 | 其他平台或额外导入方式 |
| 主要输入 | AppID、累计时长、双源标签特征；成就小样本独立预览 | 成就全量接入、近期行为、明确评价与机制反馈 |
| 评分结果 | 十二维评分位置；可估计维度展示实验性参考分位，不可估计维度展示原因 | 用自愿用户游戏库评估并改进校准 |
| 类型摘要 | 四组倾向与双高／双低标记；完整四字母类型允许缺省 | 类型命名、原型数量及组合关系优化 |
| 结果呈现 | 可视化报告、贡献游戏、数据充分性说明、可下载分享卡 | 玩家比较、相似画像分析、游戏推荐 |
| 模型实现 | 逻辑规则、最大值聚合与独立成就预览 | 典型长度修正及其他增强模型 |

首版默认生成个人报告并导出图片，不提供公开报告链接、玩家排行榜或玩家间比较。自愿反馈用于后续验证，不是完成测评的必答问卷。

### 1.4 首版成功标准

- 对处于模型适用范围、数据充分的输入，完成从 Steam 记录到十二维参考分位、报告和分享卡的完整链路。
- 每个可展示分数都有参考分布版本、覆盖情况和可追溯的行为证据；不满足条件时明确显示无法估计。
- 同一输入快照与同一组版本产生相同结果，分享卡与报告一致。
- 完成基本数据审计、评分校准与异常场景验证后，才开放实验性测评；更深入的效度研究在第五阶段持续进行。

## 二、数据来源、用途与限制

### 2.1 数据分工

| 数据源 | 用途 | 首版角色 | 边界与待核实事项 |
|---|---|---|---|
| SteamSpy | 社区标签、票数及基础游戏元信息 | 与 Kaggle 标签合并的核心特征源 | 覆盖、标签质量、更新频率和访问限制按阶段审计；公开部署条件另行评估 |
| Steam Web API | 已验证用户可读取的游戏记录与时长 | 核心在线输入 | 受数据可见性、接口权限和可用性限制 |
| Steam Recommendations 数据集 | 聚合评论样本用户记录，构建参考分布，并支持离线验证 | 第一阶段已导入的核心离线输入 | 评论样本不等于完整游戏库；字段含义和时间口径已核查；上游发行版本未确认，使用限制不属于第一阶段本地审计通过条件 |
| Steam 商店数据 | 标签不足时补充游戏描述与机制证据 | 按审计结果引入 | 不假定长期存在稳定、完整的采集接口 |
| IGDB | 候选背景、主题与玩法信息 | 后续可选 | 先评估新增信息价值，再增加接入依赖 |
| SteamMaho、Quantic Foundry、GMI | 机制分类或游戏动机研究的候选参考 | 研究参考 | 不作为现成的玩家评分或本项目效度证明；采用前补齐准确出处 |

首版合并 SteamSpy 与已导入 Kaggle 标签，不增加游戏数据库依赖；两源可能共享上游，不把一致命中当作独立准确性验证。

### 2.2 来源入口与核验记录

- [SteamSpy API](https://steamspy.com/api.php)
- [Steam Web API 文档](https://partner.steamgames.com/doc/webapi)
- [Steam OpenID 登录说明](https://partner.steamgames.com/doc/features/auth)
- [IPlayerService 与 GetOwnedGames](https://partner.steamgames.com/doc/webapi/IPlayerService)
- [Game Recommendations on Steam](https://www.kaggle.com/datasets/antonkozyriev/game-recommendations-on-steam)
- 后续候选：[IGDB](https://api-docs.igdb.com/)、[SteamMaho](https://steammaho.com/mechanics)、[Quantic Foundry](https://quanticfoundry.com/gamer-motivation-model/)。

2026-10-13 方案核对已确认 Steam 官方文档区分身份验证与游戏数据可见性。SteamSpy 的一个 [AppID 730 详情样本](https://steamspy.com/api.php?request=appdetails&appid=730)返回了标签票数，但平均及中位游玩时长字段为零；这只能说明相关字段需要审计，不能据此推断整个来源的覆盖情况。

第一阶段全量导入、字段审计、覆盖统计、候选选样和标签采集结果见 [阶段状态](docs/STAGE1_STATUS.md)。本地归档以 SHA-256 固定；Kaggle 上游发行版本仍未确认。SteamSpy 公开部署用途未评估，不由本地审计通过状态推断。

### 2.3 Steam 身份与数据可见性

Steam OpenID 用于验证身份并取得 SteamID。用户在 Steam 官方页面登录，本站不收集 Steam 密码。

身份验证成功不表示本站可以读取私有游戏详情。GetOwnedGames 的结果取决于资料可见性及接口行为；接入时应核实普通 Web API 使用方式、所需密钥及参数，不直接照搬面向合作方的示例端点。

需要检查已游玩免费游戏的包含参数，避免默认过滤造成输入遗漏。可见但未游玩的游戏可用于解释库状态，不作为正向游玩证据。

空响应、字段缺失或请求失败不能直接解释成“用户没有游戏”。只有响应足以支持结论时才显示具体原因，否则提示无法读取并提供重试或检查可见性的指引。

### 2.4 评论样本与在线游戏库的差异

参考群体定义为：**所选版本 Steam Recommendations 数据集中，经统一清洗、具有可用游戏特征和时长记录的样本用户**。

- 只评论部分游戏、主动写评论、游戏热度和数据采集时间都会影响样本分布。
- 在线游戏库与离线评论记录的观察范围不同；使用相同的计算公式只能统一计算口径，不能消除选择偏差。
- 参考样本的用户标识不默认等于 SteamID，不与在线账号直接关联。
- 首版按可观察游玩记录累计证据，不把差评对应的游玩时长自动解释为喜欢；明确推荐标签留作验证目标或后续增强信号。
- 每名合格样本用户在参考分布中计为一个观测，不按评论条数重复计入同一个用户画像。

产品统一使用“**评论样本参考分位（实验性）**”。这既不是全体 Steam 玩家的百分位，也不是对某类游戏的喜欢概率。

### 2.5 数据审计口径

审计至少包括：

| 指标 | 口径 |
|---|---|
| 游戏匹配率 | 输入中成功关联游戏元数据的去重 AppID 数／输入去重 AppID 数 |
| 标签覆盖率 | 输入中达到有效标签规则的去重 AppID 数／输入去重 AppID 数 |
| 特征可用率 | 输入中满足当前计分特征完整性规则的游戏数／输入游戏数 |
| 时长加权覆盖率 | 可计分记录的已知正时长之和／读取记录的已知正时长之和 |
| 用户记录分布 | 每用户可观察及有效游戏数量、有效时长、缺失比例和过滤前后样本量 |
| 标签质量 | 有效标签数量、票数分布、噪声及不同类型游戏的缺口 |
| 时间与更新 | 数据集版本、采集时间、标签快照时间、时长与评论时间的含义 |

时长未知的记录另报数量，不当作零时长；分母为零时覆盖率不可计算。离线评论样本覆盖率和在线试用样本覆盖率分别报告，前者不能代替后者。未取得在线试用样本时，明确标注线上覆盖率待实测。

## 三、十二维特征定义及类型展示

### 3.1 十二个候选维度（首版实验方案）

| 代码与名称 | 操作性定义 | 正向证据示例 | 解释边界 |
|---|---|---|---|
| P · Planning 规划 | 跨多个行动步骤进行资源配置、预判和长期决策 | 回合策略、长期经营、资源规划机制 | 不等同于现实规划能力；Strategy 标签只是候选证据 |
| R · Reaction 反应 | 对实时变化进行快速判断、瞄准、节奏或精确执行 | 动作时机、快节奏战斗、节奏与操作要求 | 不代表实际反应速度，也不等同于难度 |
| G · Guided 引导 | 在明确任务、目标、流程或进度结构中行动 | 清晰关卡目标、任务链、线性推进 | 不等同于简单，也不因缺少开放标签而自动成立 |
| O · Open 开放 | 自主选择目标、路线或行动方式并探索可能性 | 沙盒、自由探索、多路径解决问题 | 不只指地图面积；开放世界标签不保证高自主性 |
| M · Mechanics 机制 | 反复理解、组合和掌握可交互的规则系统 | 构筑、系统联动、资源循环、机制实验 | 不等同于所有游戏都有的基础操作，也不排斥叙事 |
| N · Narrative 叙事 | 以角色、情节、世界叙述或剧情选择驱动体验 | 故事推进、角色关系、叙事选择 | 不等同于文字量或作品质量；不因机制弱而自动得高分 |
| H · Hardcore 高压 | 在较高失败代价、挑战要求或持续压力下投入 | 高难度关卡、惩罚性失败、紧张挑战机制 | 不等同于玩家水平、重度消费或现实风险偏好 |
| C · Casual 舒缓 | 在较低压力、宽容失败条件或自主节奏下体验 | 放松氛围、宽容试错、低压力活动 | 不等同于低质量、短时长；游戏内高压与舒缓内容可并存 |

| SOLO · 独玩 | 单人体验支持 | Singleplayer | 不证明玩家实际选择单人 |
| SOCIAL · 社交 | 玩家间互动机会 | 社交推理、派对、多人 | NPC 关系不算玩家社交 |
| COMP · 竞争 | 玩家间胜负对抗 | PvP、竞技 | 不等同于高难度或高压 |
| COOP · 合作 | 玩家共同完成目标 | 合作、团队结构 | 可与竞争同时有高证据 |

上述定义描述希望解释的方向；实际计算限定为标签支持程度。六组分别展示，不表示统计独立或经验证的心理因素。

### 3.2 游戏标签支持程度与逻辑规则

每款游戏生成 P、R、G、O、M、N、H、C、SOLO、SOCIAL、COMP、COOP 十二维向量，已知值在 [0,1]，各维之和不固定。

首版取消人工标注和修订。SteamSpy 与 Kaggle 按 AppID 取标签并集，统一大小写、空白及明确同义词，不模糊匹配。SteamSpy 只纳入正票标签，票数不改变支持强度；Kaggle 不补造票数，两源重复不叠加。

直接、相关、宽泛证据分别赋 1.0、0.5、0.25，每维取命中最大值。规则及理由见 gamepersona/rules/tag_rules_v1.json，首版 48 条。规则含义或权重变更必须使用新版本，不根据统计自动调权。

有可用标签时，某维未命中记零，表示零标签证据而非机制不存在；两源均不可用时十二维未知。全零向量保留但不进入玩家共同计分集合。输出保留来源、原标签、票数、命中规则、理由和版本。

固定候选全集自动生成特征，分热门、分层、账号及账号新增集合比较两种单源和双源结果，报告完整／可计分覆盖、逐维正证据、全零、未知、新增命中与未映射标签。取消人工校验集、人工误差与一致性门槛，自动验收仅证明规则执行可靠，规范见 docs/STAGE2_QUALITY_TARGETS.md。

### 3.3 两端水平与相对倾向分开表达

每组两端使用可展示的玩家参考分位 \(A,B\in[0,100]\)，计算：

\[
D=A-B\in[-100,100],\qquad I=\frac{A+B}{2}\in[0,100]
\]

- \(D\) 描述两个参考分位的差异，不是心理偏好强度之差。
- \(I\) 只作两端总体水平的辅助摘要，不能单独决定双高或双低。
- 双高要求两端分别达到高位门槛，双低要求两端分别低于低位门槛；其他组合不强行归入这两类。
- 差异在边界容差内时显示“混合倾向”。双高／双低属于水平标记，可以与混合倾向同时出现。
- 任一端不可估计时，该组显示“待定”，不把缺失的一端当作零分与另一端比较。

“低位”只表示相对于参考样本的观察证据较弱，不等于不喜欢。高低门槛、边界容差和数据充分性门槛均为待校准参数，不预设未经验证的固定切点。

### 3.4 四字母类型的生成条件

新增两组先展示连续值，四字母摘要仍仅使用原四组。只有原四组两端均可估计、均通过数据充分性要求，且每组分差都超出边界容差时，才按 P/R、G/O、M/N、H/C 的顺序生成完整四字母类型，最多对应 16 种主标签。

存在混合或待定组时，保留各组结果，完整类型缺省。没有完整类型不影响报告查看和分享卡下载。

首版允许依据固定模板解释倾向，不依赖 LLM 生成类型。未来是否合并维度、调整组合、采用其他数量的玩家原型，由验证结果决定。

## 四、评分、归一化与数据充分性

### 4.1 四层概念

| 层次 | 变量或输出 | 含义与范围 |
|---|---|---|
| 游戏特征 | \(x_{gk}\) | 现有标签对某方向的支持程度；值为 [0,1]，两源不可用时未知 |
| 玩家行为证据 | \(E_{uk}\) | 游玩记录对某维度的累计证据；非负、无固定总额，不是概率 |
| 评论样本参考分位 | \(S_{uk}\) | 在相近有效时长和记录数量的样本中所处位置；可估计值为 [0,100] |
| 数据充分性 | 覆盖、样本支持、贡献集中度与状态 | 决定能否解释和展示；不是未经校准的“准确率” |

### 4.2 输入清洗与有效记录

对在线游戏记录和离线评论记录使用同一份清洗与计分规范：

1. 将来源标识映射为游戏 AppID，核实来源时长单位后统一转换为小时。
2. 在同一输入快照内按用户与游戏去重；累计时长不能因多条评论或重复采集而重复相加。取值规则依赖已核实的字段时间含义，并记录在清洗版本中。
3. 负值、非有限值和未知时长标记异常或缺失；零时长记录不提供正向证据。
4. 首版使用有正时长且十二维特征完整可用的游戏构成共同计分集合 \(G_u\)，保证十二维及参考条件使用同一观察集合；全零向量亦排除。缺失特征的游戏暂不计分，并体现在覆盖率与排除原因中。
5. 不把未玩、未拥有或未评论的游戏视为负向偏好。

定义：

\[
H_u=\sum_{g\in G_u}t_{ug},\qquad N_u=|G_u|
\]

\(H_u\) 是纳入模型的有效记录时长，\(N_u\) 是有效游戏数量；都不是账户全部历史投入。原始读取范围、排除记录及覆盖情况单独保留。

### 4.3 行为证据累计（首版实验方案）

各维度分别累计：

\[
E_{uk}=\sum_{g\in G_u}c_{ugk},\qquad c_{ugk}=f(t_{ug})\,h(x_{gk})
\]

用于实验比较的简单基线为：

\[
f(t)=\log(1+t/t_0),\quad t_0=1\text{ 小时};\qquad h(x)=x
\]

该基线使边际时长贡献递减，但不能保证消除长线游戏、挂机或单游戏主导的影响。是否采用特征门槛或其他时长函数，需要与简单基线比较后冻结，不能将原稿示例中的 0.5 视为既定切点。

各维度不共享分数配额，同一游戏可以同时贡献多个维度。不将十二维得分归一为总和 100；时长占比可作描述指标或对照基线，不作为相互排斥的偏好概率。

贡献游戏按 \(c_{ugk}\) 解释其对行为证据的作用。参考分位是非线性转换，不能声称某款游戏直接贡献了可相加的若干“百分位分数”。

成就完成倾向独立计算：每款先算解锁数／当前成就总数，再按 ln(1+min(小时数,100)) 加权平均乘 100。第二阶段按正时长秩分低中高三组、组内固定 SHA-256 排序，各取最多五款已授权账号游戏，比较无上限及 50、100、200 小时上限。无成就、失败、不完整和真实零解锁分开；记录有效游戏数、游戏及正时长覆盖、有效样本量、最大权重占比。高值粗略对应偏全成就型，低值粗略对应偏主线型，不证明通关、不输出置信概率或正式阈值，不套评论样本分位，也不冒充全库结果。

### 4.4 条件参考分布（首版实验方案）

从已审计的数据集快照中，按用户聚合可观察记录，使用与线上一致的清洗、特征和评分版本，生成每名样本用户的 \((H_u,N_u,E_u)\)。

首版以有效时长和有效游戏数量构建条件经验分布：

\[
S_{uk}=100\widehat F_k(E_{uk}\mid H_u,N_u)
\]

\(\widehat F_k\) 表示在匹配条件组中的经验百分位映射；并列证据值采用相同的中位秩，避免相同输入因排序位置不同而得到不同分数。

初始实验采用时长与游戏数分组，在第三阶段根据样本量与稳定性确定分组边界、最小参考样本量及适用范围。不能为每次请求临时改变分组规则；同一参考版本使用同一规则。

- 分组内样本不足、分布退化到无法区分，或输入落在模型适用范围外时，对相应维度显示无法估计。
- 需要合并稀疏分组时，在离线阶段验证并生成新的参考版本；不静默改用全体样本分位冒充条件分位。
- 在线游戏库与评论记录仍存在选择偏差，即使 \(H_u,N_u\) 相近也不保证两类输入可直接等同。报告持续保留实验性标记，后续用自愿用户样本评估迁移偏差。
- 条件归一化不自动消除游戏流行度、供给、价格、好友影响和接触机会造成的偏差。

例如，某维参考分位为 80，仅表示该行为证据在指定评论参考样本和条件口径下处于较高位置，不表示“80% 喜欢”或“超过 80% 的全部 Steam 玩家”。

### 4.5 数据充分性与展示决策

数据充分性同时考虑：有效记录数量、已知时长覆盖率、特征质量、参考组样本支持、模型适用范围，以及是否由少数游戏贡献了绝大多数证据。

| 情形 | 内部含义 | 用户可见行为 |
|---|---|---|
| 输入无法读取或时长缺失 | 观察信息未知 | 提示原因或可操作的下一步，不输出零分 |
| 可读取记录均为零时长 | 无正向游玩证据 | 显示暂无足够游玩记录 |
| 特征缺失或覆盖率不足 | 可计分记录代表性不足 | 展示覆盖情况，抑制未通过充分性要求的分位与类型 |
| 有足够有效记录但某维证据低或为零 | 在已知规则下观察证据较弱 | 参考分布有效时可展示低证据及其参考位置，不解释为不喜欢 |
| 参考样本不足、退化或输入超范围 | 无可靠参考位置 | 保留可解释的行为证据，但分位显示无法估计 |
| 单游戏高时长或贡献高度集中 | 画像可能主要反映少数游戏 | 明确提示集中性；是否足以展示分位按第三阶段冻结的规则判断 |

首版用事实指标与状态说明充分性，不拼凑“置信度 95%”之类未经验证的数值。重采样结果只能说明在指定扰动下的稳定性，不能直接解释为推断真实偏好的概率。

## 五、报告、分享卡及异常状态

### 5.1 可视化报告

报告按以下顺序组织：

1. **结果摘要：** 游戏偏好画像、实验性标记、可用的四字母类型或混合／待定说明。
2. **十二维评分：** 六组双端分数条及数值，统一 0～100 刻度；不可估计项留空并显示原因，不绘制为零。
3. **组合解读：** 分别显示相对倾向和双高／双低标记，使用固定模板描述观察到的证据。
4. **贡献依据：** 各维主要贡献游戏、时长、对应特征与规则依据；仅在个人报告中展示明细。
5. **数据说明：** 读取时间、纳入游戏数量、已知时长覆盖率、排除情况、参考样本定义及版本。
6. **分享入口：** 预览并下载与当前报告结果一致的图片。

完整报告同时保留底层行为证据和展示分数。普通阅读界面以用户能理解的说明为主，版本及规则详情放在说明区域。

### 5.2 分享卡（首版必交）

默认导出 PNG 图片，包括十二维摘要、可用类型或混合／待定提示，以及“评论样本参考分位 · 实验性”标记。

- 不默认包含 SteamID、头像、游戏库明细、贡献游戏或公开报告链接。
- 使用当前报告的同一输入快照和结果版本；图片导出不重新计算另一份分数。
- 四字母类型缺省、部分维度不可估计时仍支持导出；缺失状态与报告保持一致，不填充虚构数值。
- 尚未生成任何报告时不提供测评结果卡；已生成的不足提示报告可以按实际状态导出。
- 支持中文、较长文案和缺失状态，导出图中文字、标记与分数应清晰、无截断。

### 5.3 异常状态与用户路径

| 状态 | 处理 |
|---|---|
| 登录取消或验证失败 | 显示登录未完成并允许重新登录，不创建成功测评结果 |
| 游戏详情不可见或响应不足以判断 | 说明读取受限，提供可见性检查与重试指引，不断言空库 |
| 确认可读取但无有效游玩 | 显示数据不足，解释有效记录条件 |
| 超时、限流或来源服务异常 | 返回暂时失败状态并允许重试，不把失败缓存成零游戏 |
| 部分游戏未匹配或标签不可用 | 报告排除项与覆盖率，按充分性规则决定可展示结果 |
| 参考分布无法支持评分 | 对应维度留空，保留已有行为证据说明 |
| 某组边界接近或某端不可估计 | 显示混合或待定，完整四字母类型缺省 |
| 分享图片生成失败 | 保留当前报告并允许重新导出，不改变评分结果 |

### 5.4 数据使用边界

解释读取内容和用途，提供退出与删除个人记录、关联和报告的机制。个人报告默认不公开；将在线用户记录纳入研究或后续参考群体需要单独的自愿参与约定。

上线前明确实际保存字段、保留周期和删除范围，并验证对应流程。第三方数据集的许可与平台使用条件在数据审计中单独记录，不因公开可访问而假定可以任意使用。

## 六、系统架构与核心数据对象

### 6.1 离线与在线流程

```text
离线特征准备：SteamSpy / 经核实的补充来源
              → 原始快照 → 标签清洗 → 规则映射 → 版本化游戏特征库

离线参考准备：Steam Recommendations 数据快照
              → 用户记录清洗 → 关联同一游戏特征版本
              → 用户行为证据 → 条件分布与适用范围 → 参考分布版本

在线测评：Steam 登录 → 可见游戏记录快照
          → 共享清洗与评分模块 → 行为证据与覆盖情况
          → 匹配兼容参考分布 → 分位与充分性状态
          → 类型与解释 → 固定版本报告 → 同版本分享图片
```

先准备特征与参考分布，再开放依赖分位数的测评结果。线上与离线共用计算逻辑，不能维护两套含义相近但规则不同的算法。

### 6.2 技术建议

| 技术 | 职责 |
|---|---|
| Python | 标签处理、特征构建、共享评分、统计分析与验证 |
| DuckDB + Parquet | 大规模离线评论记录处理及参考样本分析 |
| PostgreSQL | 游戏特征、在线用户关联、输入快照索引、报告与版本元数据 |
| FastAPI | 登录与会话、数据读取、测评及报告接口 |
| React | 十二维可视化、状态说明、分享卡预览与下载 |

首版以简单服务和离线批处理为起点，不引入分布式计算作为前置条件。LLM 不负责最终分数、类型或首版必须的解释文本。

### 6.3 核心数据对象

以下为逻辑对象，不是最终建表或 API 字段清单。

| 对象 | 需保留的信息 |
|---|---|
| 游戏元数据与原始标签 | AppID、来源、原始值、采集时间及快照标识 |
| 游戏特征版本 | 十二维定义、映射规则、支持分数、来源状态、命中依据及规则哈希 |
| 在线用户关联 | 内部用户标识、已验证 SteamID、会话及数据使用状态 |
| 用户记录快照 | 可观察记录、时长原始口径、清洗版本、排除原因和采集时间 |
| 离线数据集快照 | 来源版本、文件及清洗记录、逻辑字段映射、许可核验与样本选择规则 |
| 参考分布版本 | 样本定义、兼容特征和评分版本、条件分组、样本量、支持范围及验证摘要 |
| 模型配置版本 | 时长与证据函数、充分性规则、高低门槛、边界容差和实验记录 |
| 报告版本 | 输入快照、依赖版本、证据、可空分位、评分状态、覆盖指标、贡献游戏及可空类型 |
| 分享产物 | 所属报告版本、卡片模板版本及导出信息，不引入第二套计算结果 |

原始记录与清洗结果需要可追溯。更新特征、参考分布或模型参数时生成新版本，不静默覆盖旧报告；报告重算明确生成新结果。删除个人数据时按已定义范围处理其快照、报告与服务端保存的分享产物。

### 6.4 模块接口边界

- **采集模块：** 返回输入快照与读取状态，保留未知／失败，不伪造空输入。
- **特征模块：** 返回各游戏十二维特征、依据、质量状态与版本。
- **评分模块：** 输入记录快照与固定版本配置，返回行为证据、有效记录、覆盖指标和贡献游戏。
- **归一化模块：** 输入证据及 \(H_u,N_u\)，返回可空分位、参考支持情况及不可估计原因。
- **解释与报告模块：** 根据同一计算结果生成组合标记、可空类型和模板说明；不改写分数。
- **分享模块：** 消费固定报告结果，按默认公开字段范围生成图片。

报告必须能够同时表达“有行为证据但无参考分位”“部分维度可估计”“类型缺省”等情况，不能要求每项必有数值或完整类型。

## 七、阶段路线及验收标准

依赖顺序：**数据审计 → 特征模型 → 评分与参考分布 → 测评与分享 → 验证与迭代**。

前四阶段完成首版实验性产品，第五阶段持续研究其适用性和效度。前端样式可以先用明确标识的示例数据验证，但示例结果不能替代真实评分链路的验收。

### 7.1 第一阶段：数据审计

- **输入：** 三个核心来源入口、预期使用场景和十二维候选定义。
- **任务：** 获取可追溯的数据样本／快照；核实 Kaggle 字段、时长及评论时间含义；核实 Steam 接入条件；完成游戏匹配、去重、标签与时长质量分析。
- **产出：** 来源说明与字段证据记录、按本地文件内容哈希固定的数据快照、清洗规范草案、第二节所列指标、首批游戏集合和可重复采集／导入流程。
- **通过标准：** 本地数据内容可校验且处理可复现；用户记录可关联到游戏及已知时长；覆盖、缺失和过滤损失均有可复核统计；授权账号读取、3000 款基础候选及其标签采集路径可复现。上游发行版本号与公开部署许可不作为本地数据审计的通过条件，须如实记录为未核实／未评估；本阶段通过不代表数据获准公开发布或再分发。为后续特征校验登记候选质量目标，不以“大部分可用”作为唯一结论。
- **未通过处理：** 对明确标签缺口评估补充来源或收窄支持范围。参考数据无法满足条件时暂停分位测评的产品验收，记录阻塞项；不得用虚构参考分布代替。

### 7.2 第二阶段：自动特征模型

- **输入：** 第一阶段固定快照、候选集合与本地已授权账号。
- **任务：** 固定十二维标签支持定义，自动生成全部候选特征，比较单源／双源覆盖；真实读取成就分层小样本，计算时长加权预览和敏感性。
- **产出：** 版本化规则、带命中理由的特征库、分组覆盖报告、成就样本及充分性报告、自动边界检查和离线重算。
- **通过标准：** 正值追溯规则，零证据与未知分开；去重、最大值及单调性正确；成就完整匹配、失败不填零；覆盖缺口完整报告；固定输入与版本离线重算一致。执行通过不代表实际偏好准确性经过验证。
- **未通过处理：** 修复执行问题并新建快照，保留覆盖缺口；不通过猜测机制或扩大标签含义满足覆盖门槛。

### 7.3 第三阶段：评分与参考分布

- **输入：** 数据集快照、已冻结特征版本和共享清洗规范。
- **任务：** 计算用户行为证据；比较对数时长等候选方案；构建条件分布；检查样本量、并列值、分布退化和支持范围；分析覆盖率、集中度与分组设置对结果的影响。
- **产出：** 可复现的计算流程、参考分布版本、参数与适用范围、边界案例结果、敏感性分析和线上／离线共用口径说明。
- **通过标准：** 相同输入和版本结果一致；十二维可以同时高或同时低；缺失和参考不足路径完整；展示门槛、分组规则和类型阈值在调参后冻结，并在独立样本及边界案例上核验。明确记录评论样本向游戏库输入迁移尚未消除的偏差。
- **未通过处理：** 调整分组或评分配置并重新验证；对不能支持的维度或输入返回不可估计。若尚无足够适用范围支持有效测评，不将数据不足报告冒充首版成功交付。

### 7.4 第四阶段：测评与分享

- **输入：** 兼容的特征、模型和参考分布版本，以及第五节报告规范。
- **任务：** 接入 Steam 登录及读取；建立固定版本报告；实现十二维可视化、组合解读、贡献依据、异常状态、PNG 预览和下载；落实个人数据访问及删除流程。
- **产出：** 可实际使用的首版网站、正常与不足状态的示例报告、对应分享图片和端到端验收记录。
- **通过标准：** 对有效输入完成登录至分享的全链路；第七节场景检查全部通过；报告与图片数值、缺失状态和版本一致；不同用户不能读取对方的个人报告；退出和删除行为符合公布范围。没有完整四字母类型时仍能查看并导出报告。
- **未通过处理：** 修复对应链路或状态呈现；不通过伪造数值、隐藏实验性标记或强制生成类型来满足界面完整性。

### 7.5 第五阶段：验证与迭代

- **输入：** 冻结的实验版本、独立评价样本及自愿用户反馈；需要时间研究时另需可靠时间记录。
- **任务：** 分析十二维相关性、冗余和可区分性；用 PCA／因子分析探索结构；比较游戏类型、原始标签、十二维特征和原四组差值压缩的表现，并报告离散类型的信息损失；开展记录扰动稳定性实验和用户主观偏好校准。
- **产出：** 实验设计、数据切分、指标及不确定性、基线对比、维度调整建议、自愿用户样本的迁移偏差报告。
- **通过标准：** 结论可复现并排除已知泄露；按实验前声明的目标评价区分度、稳定性、解释价值及预测效果；如未达到目标，明确判为未通过。首版十二维是有损、可解释的压缩，不预设其必然优于完整标签。
- **未通过处理：** 修改维度、归一化或展示主张，生成新版本并重新验证；必要时限制类型输出。成就全量接入、玩家比较与推荐另立后续阶段，不自动扩大首版范围。

预测实验必须从玩家输入中移除目标游戏的记录及其对 \(E,H,N\) 等派生量的贡献，目标评价不能进入画像。特征调参、参考分布拟合及阈值选择只使用对应训练／校准部分，保留独立评价数据。

评论日期不自动等于游玩行为发生时间，采集时累计时长也不自动等于评论时累计时长。缺少可靠历史口径时，只能声称进行了保留游戏记录的离线预测或扰动稳定性实验，不能声称验证了未来偏好预测或真实时间稳定性。

### 7.6 待校准参数与版本冻结

| 参数类别 | 冻结阶段 | 验证依据 |
|---|---|---|
| 标签支持规则、同义词与最大值聚合 | 第二阶段 | 逻辑理由、执行不变量、分组覆盖和固定版本重算；票数不调强度 |
| 时长函数、特征贡献函数 | 第三阶段 | 与简单基线对比、极端时长与贡献集中度分析 |
| 有效游戏数、覆盖率、集中度等展示门槛 | 第三阶段 | 样本分布、重采样稳定性与边界案例 |
| 条件分组、最小参考样本量、支持范围 | 第三阶段 | 各组样本支持、退化情况和分组敏感性 |
| 高低位门槛及混合倾向容差 | 第三阶段 | 分布、扰动下类型变化及解释一致性 |
| 后续模型效度目标与评价指标 | 第五阶段实验开展前 | 具体研究问题、基线与独立评价设计 |

未经校准的值标记为候选，不写成已验证阈值。每次冻结记录依据和版本；数据拟合、调参、验收各自使用哪些样本需要说明，避免在同一批样本上反复调参后声称独立验证。

### 7.7 场景检查清单

| 场景 | 预期结果 |
|---|---|
| 正常数据、参考支持充分 | 十二维分位、贡献依据及报告可生成；满足条件时生成类型 |
| 同组双高／双低 | 两端保留各自得分；水平标记不被压成单一倾向；双低不描述为不喜欢 |
| 两端差异很小 | 显示混合，不用四舍五入后的微小差异强制选字母 |
| 单游戏极高时长 | 提示贡献集中；不会仅因高时长绕过充分性规则 |
| 部分游戏缺标签或某维特征未知 | 从共同计分集合排除相应游戏并降低覆盖率，不补零 |
| 全部零时长或未知时长 | 区分无正向证据与数据未知，不输出虚构低分 |
| 有效记录充分、某维累计证据为零 | 允许描述该维弱观察证据；是否展示分位仍取决于参考分布 |
| 条件参考样本不足、退化或输入超范围 | 对应分位不可估计，不偷偷退回其他口径 |
| 登录成功但游戏不可读，或接口超时 | 身份与读取状态分别呈现，不解释为空库 |
| 完整类型缺省或部分分位缺失 | 报告和 PNG 均能表达实际状态，无虚构填充值 |
| 报告导出与模型更新 | 导出沿用所选报告版本；重算生成新报告，不混用新旧结果 |
| 重复用户游戏记录或重复计算 | 累计时长不重复求和；相同快照和版本输出一致 |
| 预测目标被保留作测试 | 目标游戏不进入画像及派生条件；独立评价信息不参与拟合 |

## 八、风险、研究假设与决策记录

### 8.1 已确定决策

| 决策 | 当前约束 |
|---|---|
| 产品受众与定位 | 个人 Steam 玩家；基于记录的游戏偏好与行为画像 |
| 首版结果 | 十二维评分、实验性评论样本参考分位、可视化报告及可下载分享卡 |
| 类型地位 | 可选摘要，混合或待定时不要求完整四字母 |
| 参考来源 | Steam Recommendations 提前进入数据审计与参考分布准备 |
| 计算约束 | 各维分别计分；未知与零分分开；可复现并追溯版本 |
| 分享默认 | 图片导出；不默认暴露 SteamID、游戏库明细或公开报告链接 |
| 后续能力 | 成就全量接入、典型长度修正、玩家比较与推荐 |

### 8.2 首版实验方案

- 使用 P/R、G/O、M/N、H/C、SOLO/SOCIAL、COMP/COOP 十二个方向与六组展示；四字母摘要暂仅取原四组。
- 合并 SteamSpy 和 Kaggle 标签，通过固定逻辑规则计算支持程度，不使用人工标注或 LLM 自动赋分。
- 使用边际递减的时长函数累计行为证据，条件分布以有效时长和游戏数量为起点。
- 将可估计分位压缩为组倾向与可选四字母类型，并保留两端水平和原始证据。

这些选择都需要绑定实验和版本。实现可复现不代表模型效度已经得到证明。

### 8.3 风险与待验证假设

| 风险／假设 | 可能影响 | 处理与验证位置 |
|---|---|---|
| 标签可以区分十二类标签证据 | 标签稀疏、营销词或粗粒度分类造成错误特征 | 第一阶段来源审计、第二阶段执行与覆盖检查；实际偏好有效性留待后续研究 |
| 十二维具有足够区分度 | 规划与机制、引导与叙事等可能高度相关 | 第五阶段相关性、降维和对照实验，允许合并或调整 |
| 游戏含有某机制即可反映玩家对它的偏好 | 玩家可能只喜欢复合游戏中的某一部分 | 首版限定为行为证据解释，后续自愿机制反馈与成就研究 |
| 时长足以支持偏好估计 | 挂机、朋友影响、游戏长度等改变投入 | 第三阶段敏感性与集中度分析，第五阶段主观反馈校准 |
| 条件分位可以直接迁移到游戏库输入 | 评论选择偏差及观察范围差异产生系统性偏移 | 保留实验性范围，第三阶段检查支持，第五阶段用自愿游戏库样本评估迁移 |
| 低位表示不喜欢 | 缺少接触机会或观察记录被误判为负偏好 | 全链路区分未知、弱证据和明确反馈，不从缺失推断厌恶 |
| 类型阈值稳定且有解释价值 | 边界用户频繁改变字母，离散压缩损失信息 | 第三阶段冻结容差，第五阶段稳定性与信息损失评估 |
| 数据持续可获得且允许预期用途 | 接口变化、访问限制、公开使用条件或时间口径影响后续产品 | 第一阶段核验并保存本地快照；公开使用条件在部署前另行评估，不由本地审计通过状态替代 |
| 预测实验不存在泄露 | 目标记录或后验累计时长造成虚高指标 | 按第七节隔离目标、拟合与评价数据，限制时间性结论 |

独玩／社交、竞争／合作已纳入十二维；成就完成倾向为独立小样本预览。深耕／广涉等扩展不属于本阶段。
