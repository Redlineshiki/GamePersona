# 共享评分口径 stage3-evidence-v1

来源适配后，每次只处理一个用户的 AppID、小时数、来源排除原因与读取状态。Steam 分钟在 normalize_steam 转小时，Kaggle 消费已有规范化小时；来源特有的评论日期/推荐标记不进入贡献公式。

同 AppID 完全相同的适配记录折叠，冲突全部隔离。仅正有限时长、完整十二维且非全零的游戏进入 G。已知零维保留，任一维未知排除整款。覆盖分母包含非冲突、未被来源隔离的已知正时长，包括特征缺失；冲突/未知时长不补零。未知数量单独保留。读取失败抑制共同集合，不冒充空库。

小时量化为 1e-8 小时整数，贡献为 1e-10 证据整数，正数四舍五入定义 floor(x*scale+0.5)。按 AppID 排序、整数求和；H 和 E 展示时转换小数。SQL 与 Python 共享时长函数及量化约定，由固定用户聚合对照与合成来源一致性测试验证。量化是可复现数值规范，不声称提升测量精度。

基线 ln(1+t)*x。固定模型可比较 100/200 小时封顶或线性诊断。各维独立相加，无总和约束。每维保存贡献、最大占比、正贡献游戏数和 (sum c)^2/sum(c^2) 有效游戏数；E=0 时集中度/有效游戏数为 null，不自动判成未知特征。

充分性检查读取状态、N、已知正时长覆盖、未知时长比例。每维集中度和参考支持由归一化阶段检查。低/零证据不表示不喜欢，游戏贡献解释对象为 E，不能拆分参考分位。

## 连续 W 正式参考

新模型 `model-stage3-weight-v3-v1` 保持上述贡献公式，增加 W_ticks/W：对共同计分游戏逐款计算 ln(1+t)，量化到1e-10后整数求和。W是基础时长权重，不是十二维证据总和。仅新模型输出这两个字段，旧模型/报告的确定性输出保持兼容。

参考 `stage3-reference-weight-v1` 固定逐人W和E观测、旧N/H层抽样率校正系数及标签版本；查询使用log1p(W)的biweight核，带宽0.10。分位是加权经验中位秩；加权有效参考数(sum w)^2/sum(w^2)至少200，无支持、退化、过于集中或范围外返回null，不回退旧N/H或总体分布。N只参与输入充分性，H不再决定参考组。

正式实现用标准Python与math.fsum，不依赖NumPy；发布前与NumPy实验逐分位核对。v3引导/机制的特征和参考一起重建，不能把新标签的贡献套进旧v1分布。零证据大并列仍有中位秩阶跃，不能保证所有零→微量正证据都稳定。
