# 第一阶段审计规范 v1

## 快照与逻辑对象

每个快照有 `source`、`snapshot_id`、状态、获取时间、运行版本、配置及产物 SHA-256。状态为 building、ready、failed。ready 快照不刷新；来源变更、规则变更或证据补充均创建新版本。SteamSpy 的 building 状态支持继续处理尚未请求的候选。

Kaggle 快照保留四个原始文件、DuckDB 数据库、规范化 Parquet 和解析拒绝记录。输入 ZIP 的完整性先检查；提取文件的哈希用于追溯。DuckDB 保留来源字段以检查重复与冲突，单条 JSON 元数据流式处理。

主要规范化表：

| 对象 | 字段与用途 |
|---|---|
| games | AppID、名称、未知产品类型；未证实的游戏/DLC 分类不猜测 |
| metadata | AppID、原始标签 JSON、清洗后标签、标签状态、来源明确的产品类型 |
| records | 匿名 user_key、AppID 原值及规范值、评论 ID、时长原值与小时数、时长状态、评论日期、推荐标记、关联状态、排除原因 |
| clean_records / quarantine | 同一记录集合按排除原因分区；不会把隔离时长并入用户画像 |
| user_summary | 清洗后可观察游戏数、正时长及零时长游戏数、已核实单位的总时长；不是完整游戏库 |
| user_observations | 清洗前各用户去重 AppID 数、缺失时长比例及过滤损失；与清洗后分布分别报告 |
| candidates | AppID、选样原因、热度及分层依据；包含账号新增 AppID，但不含账号标识 |
| report | 依赖快照、指标、阶段状态、阻塞项及内容哈希 |

## 清洗

- 匿名 Kaggle ID 使用 `kaggle:` 命名空间。账号规范化记录使用快照命名空间，不与匿名样本关联。
- CSV 全部先按字符串读取，再显式类型转换。解析坏行保存行号、原因和原文；缺少必需字段使导入失败。元数据按 JSONL 解析，坏行另存。
- 完全相同来源行折叠；同一用户游戏多个不同记录全部隔离。重复 review_id 涉及不同记录时隔离，不使用评论日期决定累计时长先后。
- AppID 必须是正整数文本，不将小数四舍五入成有效 ID。游戏或元数据同一 AppID 有冲突版本时，不选择任意一条。无有效 ID、关联缺失、异常日期/推荐标记及异常时长分别记录。
- 未知、非数值、非有限、负数、零和正时长有独立状态。未确认单位时 `duration_hours` 为 null；零时长不是正向证据。已确认单位的分钟除以 60，小时保持原值。
- 推荐标记原样保留。差评记录不会因推荐为 false 而删除，也不把时长反向计入任何维度。
- 作者公开管线证明 `hours` 为采集网页时显示的累计小时，评论日期独立解析；每行采集时点未导出，不能将快照打包日期视为全体记录统一截至日期。`review_id` 为导出生成 ID，只在同一数据快照内用于冲突检查，不作为跨版本稳定的 Steam 评论 ID。匿名 `user_id` 由 StringIndexer 编码，同样不在未取得映射证据时跨导出版本关联。
- 作者该版本解析器对千位逗号可能丢失前缀，解析失败默认 `0.0`。保留来源小时值及零值分类，但不能断言零值必然是实际零时长，也不能从当前 CSV 反推丢失的高位。不自动“修复”成猜测的累计时长；来源实现证据与适用边界见 [核查记录](STAGE1_EVIDENCE_RESEARCH.md)。
- 标签去掉空白项和完全重复项，不以票数推断八维强度。SteamSpy 标签要求字符串标签及非负整数票数；至少一个正票标签才记 available。空、零票、异常格式与网络失败分开。

## 指标

离线和账号实测分别计算，分母为对应输入中格式有效的去重 AppID。无效 AppID 的记录另报，不静默消失。

| 指标 | 分子 / 分母 |
|---|---|
| 游戏匹配率 | 关联唯一可用游戏元数据的 AppID / 输入有效 AppID |
| Kaggle 标签覆盖 | 具有可用 Kaggle 元数据标签的 AppID / 输入有效 AppID |
| SteamSpy 采集覆盖 | 有终态尝试记录的 AppID / 输入有效 AppID |
| SteamSpy 对应条目返回覆盖 | 正常返回对应 AppID 的记录 / 输入有效 AppID |
| SteamSpy 标签覆盖 | available AppID / 输入有效 AppID |
| 返回条目后的标签可用率 | available AppID / 正常返回对应 AppID 的记录 |
| 元数据时长覆盖 | 匹配元数据的已知正小时数 / 输入已知正小时数 |
| 标签时长覆盖 | available 标签记录的已知正小时数 / 输入已知正小时数 |

后两项只有单位已确认时计算，并明确不是可计分时长覆盖。分母为零时比率为 null。八维特征可用率和可计分时长覆盖率为 null，并标记待第二阶段。

选样补充报告另按 3000 款基础样本、热门与分层各 1500 款、授权账号以及账号新增集合计算标签覆盖，并区分 SteamSpy 缺口是否仍有 Kaggle 元数据标签。各组有交集，不相加；所选集合的覆盖不能外推为全量游戏覆盖。账号新增候选中的标签占位值不当作真实元数据缺失，补充分析会查询完整 metadata 表。

冲突的用户游戏或评论 ID 记录，其累计时长不进入加权覆盖的分子和分母，数量另报；不会通过覆盖统计将冲突时长重复求和。

审计计算版本 `stage1-audit-v2` 使用单线程固定扫描和补偿求和计算全量时长覆盖，避免并行浮点累加导致重算哈希漂移。导入仍可多线程，数值不通过粗略四舍五入掩盖差异。旧 v1 报告按其保存的计算版本重算；v1 在全量小数时长下可能因原有并行求和而不一致，应生成新的 v2 报告，不改写旧报告或放宽哈希检查。

全量统计还包含输入/解析拒绝/重复折叠/规范化/隔离/清洗后数量、排除原因、时长状态、用户游戏数与时长分布、日期范围、时长高频值及最大值集中、标签数量、票数、产品类型和来源状态。上限集中只描述观察现象，不自动证明截断或真实上限。

## 阶段通过条件

数据集版本、单位与时间语义有明确记录；存在关联到游戏及已知正时长的离线记录；3000 款基础选样及账号 AppID 的标签尝试已完成；至少有可用标签；至少一个授权账号真实读取成功；许可和来源证据满足预期用途。

自动测试使用合成小数据与固定 HTTP 响应。合成数据不用于证明阶段通过，不成为模型参考分布。工具实现状态在实施记录中说明，真实报告只有 passed 或 blocked；无法满足条件时保留统计并列出原因。
